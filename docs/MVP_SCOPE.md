# MVP 范围与风险边界

状态：设计判断；v0.1.0 已实现 Git/路径/输出三个核心检查域，其余组不在首版范围。核对日期：2026-10-27。

## 运行契约

首版为 Python 标准库优先的 CLI 检查器 + 符合 Agent Skills 规范的 `SKILL.md`。输入为显式项目根目录、入口脚本以及可选的配置/输入/输出路径。默认离线、只读、无训练执行、无导入用户模块。报告既可供人阅读，也有稳定 JSON 格式供 Agent 解释。`unknown` 与工具错误单列（工具错误以固定错误码/退出码区分），不能被“无 warning”掩盖。没有显式输入时，不猜测整个科研目录。与 [trainproof](https://pypi.org/project/trainproof/0.22.0/) 等直接竞品的重叠意味着 JSON、规则 ID 和零依赖只是必要品质，不是差异化主张（2026-10-27 核对）。

## 六组检查

| 组 | 可静态检测的事项（评估，不等于首发承诺） | 误报/漏报来源 | 首版不支持 |
| --- | --- | --- | --- |
| Git | 根是否为普通仓库、HEAD 是否存在、显式入口是否有暂存/工作树修改、入口是否被索引跟踪；仅调用固定的只读 Git 子命令，不扫描其他未跟踪文件。 | 未提交修改可能是有意实验；Git 子模块、忽略文件、LFS 或快照机制另有追溯方式。 | 自动提交、清理工作树、上传远端、扫描完整历史或认定“可复现”。 |
| 环境 | 当前解释器版本/平台、显式声明的依赖文件是否存在、选定包的已安装版本是否可读；报告当前环境与项目声明缺失。 | 容器/集群训练环境可能不同；依赖文件存在不代表锁定有效；包名与 import 名不总一致。 | 自动安装、求解依赖、解析任意 YAML/Conda、验证 GPU/CUDA 兼容或证明环境可重建。 |
| 随机性配置 | 对限定 Python 源码以 AST 识别明显的固定 seed 调用/赋值及缺失的声明，作为“观察到/未观察到”提示。 | 种子可能在函数/配置/框架封装中设置；发现 seed 也不保证确定性，多进程及算子仍可能非确定。 | 执行源码、证明全链路确定性、覆盖所有框架/分布式训练，或将“未发现”判为确定故障。 |
| 路径 | 对显式入口和输入检查存在性、类型、相对路径基准，以及入口物理目标是否越出根目录；只做元数据探测，输入可在根外。 | 数据可能稍后挂载或由任务生成；符号链接、UNC、大小写、权限会改变实际解析。 | 遍历/读取原始数据、校验内容/标签、自动修复路径、追踪动态拼接路径。 |
| 输出风险 | 对显式输出目标检查已存在、类型，以及与入口/输入/根的同路径或祖先/后代冲突；给覆盖风险提示。 | 既有文件可能允许续训；程序可能自己生成唯一文件名；静态目标可能与运行时不同。 | 删除/移动产物、创建测试文件、预测运行时所有写入、计算所需磁盘容量。 |
| 运行追溯 | 检查是否提供入口、命令/参数来源、Git SHA（如可得）、环境声明、输出目标等最小记录要素；仅报告“准备信息缺项”。 | 自定义 tracking、调度器或实验平台可能另行记录；元素存在不证明内容准确。 | 运行后指标/产物追踪、自动上传、生成含敏感路径的公开 manifest、声称完整 provenance。 |

**裁剪裁决：** 首个可用版本只承诺三个高置信检查域：① Git 状态与指定入口版本控制；② 显式输入路径存在/类型/根目录关系；③ 显式输出目标的已存在与输入冲突。入口、命令参数来源、解释器信息和追溯要素可作为报告元数据及 `unknown` 提示，不作为通过门槛。随机性 AST 规则、依赖一致性、完整追溯评估均推迟到误报样例验证后。六组都已在上表评价，但并非六组都要首发实现。

## 标准库与依赖

**已验证的语言能力（按 Python 标准库 API 设计，实施前仍需跨平台测试）：** `argparse` 处理 CLI；`json` 输出；`pathlib`/`os` 读取显式路径元数据；`subprocess` 固定参数调用 Git；`ast` 解析 Python 源码而不执行；`sys`/`platform` 与 `importlib.metadata` 读取当前环境；`tomllib` 可读 TOML（需 Python 3.11+）；`configparser` 可读 INI。文本读取需限制文件数量/大小并处理编码错误。Git 是可选外部可执行程序，不是 Python 包。[Python `tomllib`](https://docs.python.org/3.11/library/tomllib.html) · [`ast`](https://docs.python.org/3.11/library/ast.html) · [`importlib.metadata`](https://docs.python.org/3.11/library/importlib.metadata.html) · [`subprocess`](https://docs.python.org/3.11/library/subprocess.html)（2026-10-27 核对）。

**设计判断：** 首版运行时可以零第三方 Python 依赖；建议最低 Python 3.11，以使用 `tomllib`。这不是独有卖点，[trainproof](https://pypi.org/project/trainproof/0.22.0/) 也声明核心零运行时依赖（2026-10-27 核对）。YAML 是常见 ML 配置，但标准库没有通用 YAML 解析器；首版将 YAML 内容标为未解析，或只依据用户显式传入的值检查。若真实用例显示 YAML 必不可少，再考虑一个可选且明确授权的解析依赖，不以脆弱正则伪装完整解析。

## 工程与安全风险

- **Windows/Linux：** 路径分隔符、盘符/UNC、符号链接、大小写、可执行文件查找及 Git 输出编码不同。使用 `pathlib`、固定 argv、不经 shell、NUL 分隔 Git 输出；测试合成目录和特殊字符路径。跨平台没有测过前，不声称兼容已验证。
- **私人数据：** 只对用户显式指定根目录及候选源/配置文件做有界静态检查；不打开训练数据、不打印环境变量值、凭据、完整路径或源码片段；对输出路径作遮蔽。Agent 仅接收脱敏结果，默认不联网。预检本身不能保证项目无隐私泄漏。
- **只读：** 不创建文件、不执行训练/用户代码、不调用会修改仓库的 Git 命令。输入文件可能被并发修改，结果应注明检查时点。Git 子命令的只读性已通过固定 argv、环境隔离和配置覆盖在合成测试中核验；TOCTOU 和旧版 Git 差异仍是限制。
- **Skill 兼容：** 标准要求 `name` 与 `description`，名称与目录一致，避免依赖各宿主私有 frontmatter；脚本路径相对 skill 根目录。Codex 与 Claude Code 的项目级发现路径不同，需分别做安装/调用验证；不要把 `allowed-tools` 当作跨宿主权限保证。[Agent Skills 规范](https://agentskills.io/specification) · [Codex 说明](https://learn.chatgpt.com/docs/build-skills) · [Claude Code 说明](https://code.claude.com/docs/en/skills)（2026-10-27 核对）。
